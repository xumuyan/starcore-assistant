# 全局按键语音输入设计

日期：2026-11-01。状态：用户已确认完整方案并授权继续开发。此文档描述验收目标，不表示功能已经实现。

## 目标与现有功能

在任意可编辑输入框中，按快捷键开始口述，再按同一快捷键结束，本地识别后将文字写入光标位置。Esc 取消。输入文字不自动发送，不按回车，不进入助理对话、播报或 Codex 投递流程；即使口述包含“让 Codex”，也只作为输入文字。

原有唤醒对话、云桥聊天、可选 DeepSeek 润色、Fish/系统声音、项目选择、加密存储、微信提醒和原聊天续写保持原有行为。语音输入独立启用，默认关闭；启用后不要求同时运行 SpeakMore。

## 实现方式选择

| 方式 | 收益与代价 | 结论 |
| --- | --- | --- |
| 星核新增原生输入模块，复用现有本地 ASR | 共用模型、配置与权限入口，需要新增热键、手动录音和输入适配 | 本期方案 |
| 调用外部 SpeakMore | 可使用已有能力，需要同时维护另一应用的安装、运行与配置 | 不作为当前集成方式 |
| 合并完整 SpeakMore Electron 客户端 | 覆盖范围大，会引入第二套界面、引擎与历史管理 | 不属于本期范围 |

## 用户操作

1. 在设置启用“全局语音输入”，检查麦克风、输入监控及辅助功能权限。
2. 默认快捷键为右侧 Option。设置首版提供右侧 Option、F8、F9 三个预设；功能键可能需要配合键盘 Fn 模式。保留以后增加组合键录制的接口，本期不做任意键组合编辑器。
3. 如果 SpeakMore 或其他软件仍占用同一键，用户选择不同预设或自行关闭其绑定；不修改其他软件设置。
4. 输入框保持焦点。按一下开始，再按一下结束，Esc 取消。修饰键与其他键组成正常快捷键时，不触发单独的右 Option 动作；按键自动重复不导致重复录音或重复提交。
5. 一个不抢焦点的原生悬浮条显示录音时间、真实输入电平、识别中、可选润色、已发出粘贴或失败状态。
6. 开始前模型未就绪时显示加载中，准备好后才进入可录音状态；准备期间的再次按键或 Esc 可以取消，避免漏收首句。

全局快捷键和首次权限体验在真实 Mac 上验收，不把网页中的模拟键盘事件当作系统热键证据。

## 模块与消息边界

- `client/DictationHotkey.swift`：启用开关、预设热键、按键去重、组合键排除、退出与睡眠后的清理。
- `client/DictationController.swift`：一轮输入的状态机、请求 ID、权限、原生采集与结果路由。
- `client/DictationPanel.swift`：不激活前台应用的原生悬浮条；明确的取消和复制结果入口。
- `client/DictationPaste.swift`：记录目标、检查输入焦点、临时剪贴板与粘贴，不提交输入内容。
- `client/Microphone.swift`：保持原有自动分句入口，新增显式开始/结束的采集方式，不改变旧调用语义。
- `src/assistant-dictation.mjs`：独立识别与可选润色服务，复用 `LocalASR` 和校对函数，不调用 `AssistantService.text()`、TTS 或 Codex。
- `src/assistant-host.mjs`：只新增带请求 ID 的 dictation 准备、音频、取消、结果消息；原消息类型保留。
- `client/AssistantBridge.swift`：必要桥接与音频资源协调；助理和听写不同时占用麦克风。
- `src/assistant-core.mjs` 与现有设置页：新增独立启用、热键预设与听写润色设置，旧配置采用兼容默认值并继续加密保存。

## 录音与识别

用户结束前，短暂停顿不结束整次口述。录音仅在内存中保存；单次上限 120 秒，到上限显式提示并处理已有音频。

现有 ASR 单段最多 24 秒。听写将音频按静音边界优先切分为不超过 18 秒的片段，结束时刷新最后一段；没有静音时使用长度边界。逐段识别并保持顺序，最后统一组织文本。短片段、纯静音和无有效识别结果不粘贴；不能把长录音直接传给现有单段接口。

听写使用与助理相同的 ASR 实例及串行访问约束。开始听写时暂停原唤醒采集，结束或取消后按原来的用户监听状态恢复；不擅自打开原本关闭的唤醒监听。原助理正在处理或播报时，拒绝开启听写并说明状态，避免中断既有工作或录入播报内容。

听写的 DeepSeek 润色是独立设置，默认关闭。开启后只发送本次识别文字，失败保留原文并提示，不重试、不调用云桥聊天、不读取聊天历史或项目上下文。纯本地模式不需要云桥、DeepSeek、Fish 密钥。

## 输入目标与剪贴板

开始录音前记录前台应用与可识别的聚焦元素，仅取输入目标元数据，不采集其正文。粘贴前再次确认前台应用及聚焦元素仍匹配，并等待触发键释放。无法确认、目标变化、没有输入框、密码框或权限不足时，保留本轮结果在内存中，显示手动复制入口，不转投其他窗口。

需要时短暂写入剪贴板并发出一次粘贴操作，保留原先的多格式剪贴板快照。恢复前检查 changeCount：如果用户或其他程序已经改了剪贴板，不覆盖新内容。操作串行执行，取消或过期的请求不进入粘贴。未授权辅助功能时不伪装成已经输入。

系统粘贴事件已发出不等于目标应用确认收到文字；状态说明应区分两者。终端等存在粘贴即执行风险的目标采用结果预览与手动复制，不自动粘贴。测试不向真实微信聊天、终端或其他业务应用发送文字。

## 状态与取消

状态为 `idle → preparing → recording → transcribing → polishing（可选）→ inserting → idle`；失败进入带可复制结果的 `error`，用户可清除结果回到 idle。

全流程携带请求 ID 和代次。Esc、关闭功能、退出、锁屏/睡眠或音频设备变化会使当前代次失效，丢弃未完成结果并清理采集。模型推理即使无法立即中止，完成后也不能把过期文字写入。正在处理时不再排入另一轮任务，不自动重放或重新调用付费服务。

## 数据与权限

原始录音不落盘。听写结果不进入助理聊天历史，只在当前会话内供本次插入或失败复制，清除、取消或退出后释放。加密配置沿用现有本地库，不复制外部 SpeakMore 密钥和历史。

新增的辅助功能和输入监控权限只服务于启用的语音输入模块；关闭此功能不影响原助理。权限由用户在 macOS 正常界面授权，代码只检测、说明和打开设置入口。

## 验收与交付

- 单元检查：热键状态、配置兼容、录音分段、空音频、请求取消、过期结果、焦点变化、剪贴板并发、长录音顺序及网络调用边界。
- 完整回归：已有语音、聊天、加密、项目查询、Codex 交接与微信检查继续通过。
- 构建：Mac 原生构建、架构、部署目标与签名核验。
- 隔离实测：在临时 TextEdit 文档验证系统热键、焦点不丢失、单次写入、Esc 和剪贴板恢复；浏览器输入框再验收一次。真实人声识别由用户配合，不以模拟 PCM 代替。
- 重开：启用和热键设置保持，原聊天目标、名字、唤醒词、声音及加密记录恢复。
- 记录：每个逻辑批次更新根目录日志和计划，创建带 Change-ID 的 commit，推送并核对远端。构建通过与真机通过分别记录。

翻译、划词翻译、词典、多云端识别引擎、录音历史、iPhone 和音箱不包含在本期语音输入中。
