## 范围

- 删除现有全屏动态页面（旧场景资源保留在仓库，不再作为默认界面）。
- 应用常驻后台监听唤醒词（沿用现有"沐言"唤醒链路），无任何可见界面。
- 唤醒后整条语音对话流程以桌面最上层浮层呈现；"退下/退出"隐藏全部浮层并回到待唤醒。
- 按键全局听写功能不变（右 Ctrl 等现有热键、识别、写入输入框、复制回退），仅更换呈现。
- macOS 菜单栏新增图标，点击打开置顶设置框。
- Codex 项目选择/聊天交接面板从界面砍掉；Codex 完成后的顶部弹框保留，去掉"是否开启"选择，默认直接开启，样式与设置框一致。
- 新增：语音指令打开本机应用并进入网址（如"打开浏览器进入某个网址"），作为独立批次，默认范围最小（先支持常用浏览器/Safari 与 URL 打开），不在本期承诺任意应用控制。

## 视觉状态与效果映射

四个参考效果的职责（效果按 libraries.dev 视觉自行用原生或浮层 WebView 复刻，不内嵌外部站点资源）：

| 效果 | 用途 | 状态 |
| --- | --- | --- |
| voice-ring | 唤醒后收音的桌面最上层环形动效 | 收音态 / 思考态（同一组件多状态） |
| beam | 识别文字与回复文字所在的内容框；设置框；Codex 完成弹框 | 出现于 voice-ring 下方，玻璃描边光束风 |
| voice | 文字进入 beam 框的逐词/成组浮现动画 | 识别文字与回复文字共用 |
| orbs | 按键听写提交后的思考过程 | 长条框内，Esc 取消 |

## 状态机

1. `idle-listening`：无界面，仅唤醒词监听（沿用现有常驻监听与资源策略）。
2. `wake-listening`：唤醒词命中 → 最上层 voice-ring 收音态。
3. `user-text`：识别出内容 → voice-ring 下方出现 beam 框，文字以 voice 效果填入。
4. `thinking`：voice-ring 切思考态（可以是 orbs 之外的第二种思考表现，按用户描述用 voice-ring 多状态）。
5. `reply`：回复播报，同时 beam 框内以 voice 效果逐段显示回复文字。
6. 回到 2 继续对话（连续对话保持）；用户说"退下/退出" → 隐藏全部浮层回到 1。
7. 听写（独立流程）：热键 → voice 长条框，收音时下方闪动；提交 → orbs 思考；Esc 取消；完成按现有链路写入输入框。
