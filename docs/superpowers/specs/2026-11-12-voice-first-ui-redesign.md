## 视觉状态与效果映射

用户已确认：视觉完全照参考站，不混用现有 MOSS 配色或玻璃风格。以参考站的配色、形状、动效节奏和状态变化为实现及视觉验收目标；不能仅保留相似概念就视作还原完成。效果在 Tauri 2 的本地 WebView 内离线复刻，不内嵌外部站点资源。已核查四个参考页、npm 接口及 MIT 许可并直接集成原组件，尚未完成逐状态视觉比对，不宣称已还原。参考页的 `processing` 示例与 `voice-glow@0.3.0` 开源接口不同：扫动处理态为上游 Pro hook，本批未引入；文字分词淡入为本地补充，voice 本身提供声音驱动底部光效。听写处理态使用原版 orbs。

四个参考效果的职责：

| 效果 | 用途 | 状态 |
| --- | --- | --- |
| voice-ring | 唤醒后收音的桌面最上层环形动效 | 收音态 / 思考态（同一组件多状态） |
| beam | 识别文字与回复文字所在的内容框；历史记录窗口；设置窗口；Codex 完成弹框 | 对话框位于 voice-ring 下方，其余窗口按用途置顶，外观完全照参考站 |
| voice | 文字进入 beam 框的逐词/成组浮现动画 | 识别文字与回复文字共用 |
| orbs | 按键听写提交后的思考过程 | 长条框内，Esc 取消 |

## 状态机

1. `idle-listening`：无界面，仅唤醒词监听（沿用现有常驻监听与资源策略）。
2. `wake-listening`：唤醒词命中 → 最上层 voice-ring 收音态。
3. `user-text`：识别出内容 → voice-ring 下方出现 beam 框，文字以 voice 效果填入。
4. `thinking`：voice-ring 切思考态（可以是 orbs 之外的第二种思考表现，按用户描述用 voice-ring 多状态）。
5. `reply`：回复播报，同时 beam 框内以 voice 效果逐段显示回复文字。
6. 回到 2 继续对话（连续对话保持）；用户说"退下/退出" → 隐藏全部浮层回到 1。
7. 听写（独立流程）：热键 → voice 长条框，收音时下方闪动；提交 → orbs 思考；Esc 取消；完成按现有链路写入输入框。

## 批次拆分（产品接线均未开始，参考组件已预备）

- B1 浮层基建：在 Tauri 2 壳实现跨平台非激活置顶浮层、动画帧驱动、退出隐藏接口；以现有 ReminderBanner/DictationPanel 的行为为回归目标，不直接复用 Swift 窗口实现；依赖 T0/T1 的能力验证与接口，macOS/Windows 分别验收。
- B2 唤醒浮层：wake-listening 态 voice-ring（收音态）与唤醒→浮层→识别事件接线；回归保证唤醒词与资源互斥不变。
- B3 对话浮层：beam 框 + voice 文字动画（识别文字、回复文字）、thinking 态 voice-ring、"退下/退出"退出短语隐藏；旧全屏页面下线。
- B4 听写呈现迁移：在 Tauri 2 实现 voice 长条框 + orbs 思考，Esc 取消；识别/写入/复制回退行为保持，系统热键/录音/写入由平台适配层接入，不再围绕 Swift DictationPanel 新建界面。
- B5 菜单栏历史与设置：macOS 菜单栏 / Windows 系统托盘统一入口，点击菜单栏图标先出现「历史记录 / 设置」按钮组，选择后再打开对应的 beam 置顶窗口，不直接跳入设置；历史记录沿用现有加密数据与读取链路，设置项沿用现有字段与保存流程。
- B6 Codex 收尾：砍掉项目选择/交接界面；完成弹框默认开启（移除开关 UI）并改为 beam 样式置顶。
- B7 语音打开浏览器/网址：仅浏览器意图识别与安全边界（仅白名单打开方式、不自动输入凭据、URL 需用户口述明确；仅允许 HTTP/HTTPS 网页，不执行脚本、Shell 或其他应用协议）；未指定时使用系统默认浏览器；独立开关，默认关闭，符合"新功能默认关闭"。
- B8 回归与真机验收：完整 `npm test`、现有原生构建检查及新增 Tauri/Rust 构建测试；macOS 与 Windows 分别构建安装、真人验收和验证旧配置兼容，不以 Mac 通过代替 Windows 验收（对应 T3/T4）。
