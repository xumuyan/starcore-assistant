## 发现并修复的问题

1. 首轮控制器夹具编译发现小数写法错误；完整应用构建发现 Swift catch 变量遮蔽 error 方法，改为 self.error。后续原生编译通过。
2. 独立规格复核复现：原消息门控无条件 await，让紧随的听写准备先于原聊天 busy 标志运行。改为原协议同步判定，仅新协议返回 Promise；新增回归在修复前失败、修复后通过。
3. 手动复制只显示原因，缺少设计要求的结果预览。增加最多 500 字符预览，完整结果只留在内存中供复制；测试确认取消后释放。此回归修复前失败、修复后通过。

4. 原有后端有只返回 error、不再返回 state 的终止路径，可能留下 transcribing/executing，使新听写一直误判忙碌。新增可测试状态更新规则，错误释放界面状态锁；实际播报标志和后端忙碌核验继续有效。
5. 特定静音分段让 120 秒尾段仅剩 20 毫秒，原填零会超过服务 120 秒总长。新增不规则静音边界回归先复现失败，再将临近结尾的边界前移，给尾段保留足够真实采样；验证完整采样顺序、总数及每段边界，无需放宽服务限制。
