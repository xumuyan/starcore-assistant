# SC-20261115-013 真实输入/clipboard 执行器与 TOCTOU 复查接线准备评估

## 范围与方式

按 [消费者边界审查](2026-11-15-dictation-consumer-boundary.md) 差距清单第 2 条，本批只做接线准备评估文档：评估真实输入设备写入/剪贴板执行器与 TOCTOU 复查的接线准备工作。不做任何真实接线、不调用剪贴板或输入设备、不申请任何系统权限；权限一律走 macOS 用户正常授权流程（系统设置 → 隐私与安全性 → 辅助功能/输入监控），不自动替用户授予。文中"已验证"仅指离线模型测试通过，不是生产验收；SC021 整批、T0、T1、G1～G6 保持未验收。

## 一、已验证边界（复用离线证据，只读引用）

1. **显式复制复查模型**（[复制复查/执行器边界](2026-11-14-dictation-copy-effect.md)）：`checkedAt` 是可信本地复查假设，原 token 只接受一次；`allowed=false` 确定 not-issued；`handoffAt` 只一次，冻结原 executor handle 交出完整业务正文，进入 in-flight/outcome=unknown；失联/取消/期限到达不能降格为 not-written，不能自动再复制。
2. **TOCTOU 已声明的存在性**：同一逻辑 now、source 高水位与 `allowed=true` 都不证明 OS 检查与执行原子；真实 native executor 必须在自身执行边界复查当前系统状态/权限/原 ownership；自动粘贴还须复查原 target/focus/selection/security/trigger release（不属于显式复制适配范围）。
3. **组合帧与主动投递**（[组合帧投递](2026-11-15-dictation-copy-frames.md)、[离线主动投递与子进程测试](2026-11-15-dictation-parent-child.md)、[renderer 回执协议](2026-11-15-renderer-ack-protocol.md)）：原帧归父进程一次 commit；子进程 ACK 只证明结构校验；renderer 回执协议已覆盖 prepare→展示更新→确认与单消费者认证，均为离线默认关闭。
4. **失效不等于资源停止**：hidden/展示失效与真实复制执行器 stop 分离，已有离线证明；真实执行器生命周期接线未开始。

## 二、生产差距（未实现、未验收）

1. **真实剪贴板写入未接线**：`copy-written/copy-not-written/copy-unknown` 的真实判定依赖 OS 剪贴板调用；当前只有测试模型值。无 macOS `NSPasteboard`/`pbcopy` 或等价通道选择、格式（纯文本/UTI）与冲突策略。
2. **真实输入注入未接线**：paste-issued/paste-uncertain 需要键盘事件注入（CGEvent 或宿主等价物）；无注入实现、无焦点目标校验、无注入后结果回报通道。
3. **TOCTOU 真实复查未实现**：模型 `checkedAt/observedAt` 是同步可信假设；真实"检查→交接→执行"跨异步边界，需在执行器边界二次复查锁屏/权限/目标焦点，当前无该代码路径。
4. **执行器生命周期未接线**：handoff 冻结 handle 后的真实执行器启动、超时、取消、失联上报（reportAt/stoppedAt 真实证据）无实现；不自动重启、不自动再复制策略仅在模型层。
5. **权限与授权前置缺口**：辅助功能/输入监控授权状态检测、未授权时的引导与 fail-closed 行为未实现；不得用有期限的缓存快照代替真实授权检查。
6. **正文跨进程最小化未定义**：handoff 交出完整业务正文，跨进程传输的最小化、隐私与截断策略仍未定义（差距第 6 条保持）。

## 三、解除条件

1. T0（Tauri/Rust 宿主生产通道）验收通过，存在宿主侧执行器通道与回执/结果回报；T1 按计划启动。
2. G1～G6 生产门槛逐项满足并记录证据；不得以离线回归替代。
3. 用户通过 macOS 正常授权流程授予辅助功能/输入监控权限；未授权时功能保持关闭/拒绝，不自动授予、不引导绕过。
4. 执行器边界真实 TOCTOU 二次复查实现并通过真机验收；TOCTOU 窗口只能缩小、不能声明消除。
5. 正文最小化与隐私策略形成文档并纳入守护测试；真实剪贴板/注入结果区分 written/not-written/unknown 并有真机证据。

## 四、不可推断事实与反例

1. **不能从 `allowed=true` 推断写入会成功**：反例：检查时未锁屏，handoff 后用户立即锁屏，执行器仍可能注入失败或写入错误目标。
2. **不能从 handoffAt 返回推断已发生写入**：handle 冻结只代表责任交接；反例：执行器启动即崩溃，outcome 停留 unknown。
3. **不能从 copy-written 推断粘贴目标正确**：剪贴板写入成功不等于 paste 目标校验通过；两者是独立证据。
4. **不能从离线 480 条重排通过推断真实执行器时序安全**：矩阵是逻辑轨迹，不含 OS 调度、权限弹窗、剪贴板竞争。
5. **不能从授权一次推断长期有效**：用户可随时撤销权限；每次执行边界的真实复查不可省略。
