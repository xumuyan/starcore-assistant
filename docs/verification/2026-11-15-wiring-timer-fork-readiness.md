# SC-20261115-013 真实 timer/锁屏/设置监听与真实 fork 时机权限崩溃策略评估

## 范围与方式

按 [消费者边界审查](2026-11-15-dictation-consumer-boundary.md) 差距清单第 4 条（真实 timer 与源监听）与第 5 条（真实 fork 差距），本批只做接线准备评估文档。不做任何真实接线、不注册系统监听、不 fork 生产进程、不修改默认关闭行为。权限一律走 macOS 用户正常授权流程，不自动授予。文中"已验证"仅指离线模型测试通过；SC021 整批、T0、T1、G1～G6 保持未验收。

## 一、已验证边界（复用离线证据，只读引用）

1. **源租约与 TTL**（[源租约模型](2026-11-14-dictation-source-lease.md)）：`sourceTtl` 默认 10000 是逻辑单位，不是已决定的产品毫秒/配置；显式逻辑 now 注入，无 Date/performance/调度器；lock/settings 期限互相独立，任一到期 `lostAt` 关闭当前 run；期限由 `observedAt+ttl` 计算，不由到达时间计算。
2. **无自动活性检测**：只在显式传入逻辑时间的入口识别静默超期；事件循环长阻塞不触发；期限内也可能已锁屏但通知未到；有期限的缓存不能代替真实授权。
3. **fork 边界**（[离线主动投递与子进程测试](2026-11-15-dictation-parent-child.md)）：测试 fork 固定仓库 worker，覆盖正常/协议失败/意外退出；watchdog 5000ms 默认（1～30000ms 可配）；SIGTERM→1000ms 后 SIGKILL，仅对自建子进程；close Promise 只在实际 close 事件后完成；默认 `enabled` 非真不 fork。
4. **回执协议**（[renderer 回执协议](2026-11-15-renderer-ack-protocol.md)）：prepare→展示更新→确认回执 fail-closed 与单消费者认证为离线模型，不证明真实宿主 IPC。

## 二、生产差距（未实现、未验收）

1. **真实 timer 未接线**：无系统单调时钟驱动的 TTL/背压 timer；逻辑 now 注入与真实 `Date.now`/单调时钟的映射、时钟回拨/休眠暂停对期限的影响无实现。
2. **锁屏/设置监听未接线**：无锁屏（screen will/did lock）、系统设置变化、休眠唤醒的真实监听与事件桥接；唤醒后的 run 恢复/失效策略未定义（按现有模型须显式重建，不自动复活）。
3. **fork 时机未定义**：生产 fork 的时机（首次启用 vs 会话开始）、宿主环境变量、路径与打包资源定位（runtimeEngine bundle 内 node）未接线。
4. **权限差距**：fork 的 worker 如需输入/剪贴板能力，继承宿主授权；授权状态检测与未授权 fail-closed 未实现；不自动授权。
5. **崩溃恢复策略评估**：按设计不自动重启；真实宿主下子进程崩溃后的用户可见状态（hidden + fail-closed 提示）与重启用户新动作路径未接线；SIGKILL 后残留至 OS 回收的窗口无法消除，只能声明。
6. **watchdog 真实标定缺失**：5000ms 默认在真实宿主负载下的适当性未标定；测试用短期限不代表生产值。

## 三、解除条件

1. T0（Tauri/Rust 宿主生产通道）验收通过，明确 fork 时机、环境、bundle 路径与 IPC 通道；T1 按计划启动。
2. G1～G6 生产门槛逐项满足并记录证据；离线回归不替代真机验收。
3. 真实监听桥接实现后，休眠唤醒/锁屏场景经真机验收（含唤醒后不自动复活、须新显式重建的确认）。
4. timer 实现采用单调时钟并在文档中定义休眠/回拨语义；watchdog 生产值经真实负载标定后写回配置默认。
5. 权限检测与 fail-closed 行为经真机验收；未授权路径保持功能关闭，由用户正常授权流程解锁。

## 四、不可推断事实与反例

1. **不能从逻辑期限到期推断锁屏发生**：期限是本地超时；反例：事件循环阻塞 6 秒导致 lostAt，实际系统从未锁屏。
2. **不能从唤醒监听到达推断休眠期间无写入**：休眠中 timer 暂停，期限可能未到期但外部状态已变化；真实执行仍须边界复查。
3. **不能从测试 fork 通过推断生产 fork 可用**：测试 fork 固定仓库路径与受控环境；生产 bundle 内 runtimeEngine/路径解析未验证（无 macOS 授权流程验证）。
4. **不能从 SIGKILL 发送推断进程已终止**：SIGTERM 挂起→SIGKILL→OS 回收有不可消除窗口；close Promise 只等实际 close 事件。
5. **不能从 watchdog 超时区分失败原因**：挂起、调度延迟、消息丢失均触发同一 fail-closed，模型不区分。
6. **不能从离线 watchdog 配置校验推断生产超时合理**：1～30000ms 边界校验只防配置错误，不证明 5000ms 在真实宿主足够。
